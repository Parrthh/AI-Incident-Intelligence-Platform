What happens when something breaks

In the latest chaos test, the summary was on screen within seconds of the alert arriving.

  1. Alert fires

    A Prometheus rule trips and Alertmanager posts the alert here.

  2. Stored once

    Retries and duplicates leave exactly one record, even when ten copies arrive at the same moment.

  3. Incident opens

    A new alert opens an incident. When the alert resolves, so does the incident.

  4. Summary written

    Secrets are stripped out, then an LLM writes three sentences from the alert data alone.

  5. Shown on call

    The incident list updates with the summary and the model and prompt that wrote it.

How it's built

Python, FastAPI, Postgres with pgvector, Redis, and Gemini, deployed from GitHub on every merge. A few of the decisions behind it:

Tested by breaking things
A GitHub Actions job runs the OpenTelemetry Demo, makes its payment service fail, and checks that an incident and summary appear and then resolve.
Duplicate-proof ingestion
An atomic upsert keyed on the alert's fingerprint and start time, plus a guard that a late retry can't reopen a resolved alert.
No secrets reach the model
Passwords, tokens, API keys and email addresses are redacted from every prompt. Each summary records its model, prompt version and token counts.
Every deploy is verified
After a merge, a job waits until this site reports the new commit, then checks that the database and Redis are reachable.
